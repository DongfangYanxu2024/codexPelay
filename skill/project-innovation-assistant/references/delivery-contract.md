# Delivery contract

Read this reference when producing the complete report or an implementation/iteration handoff.

## User-facing report

Lead with the recommendation and status, then keep these items auditable:

1. brief, assumptions, evidence, and hard constraints;
2. all 20 concepts in groups `G1`–`G4`, five each;
3. eligibility outcomes and reasons;
4. scores, weights, confidence, risk, and duplicate clusters;
5. distinct Top 5 with adversarial findings and score revisions;
6. Top 3 experiments with predeclared thresholds;
7. one provisional/validated selection, or no-go/pivot if none is eligible;
8. implementation changes and checks, only when requested;
9. observed metrics, provenance, iteration count, and one disposition.

Separate observed facts, external evidence, inference, and assumptions. Keep excluded and duplicate candidates in an appendix or machine-readable artifact instead of silently dropping them.

## Decision invariants

Before delivery, verify:

- the default run has exactly 20 unique candidate IDs and names;
- each portfolio contains exactly five candidates;
- every candidate checks every hard constraint;
- only all-pass candidates compete for selection;
- all six scores are in `[0, 10]`, confidence in `[0, 1]`, risk in `[0, 10]`, and weights total 1.0;
- Top 5 representatives are from distinct semantic duplicate clusters;
- every Top 3 experiment is falsifiable and has a threshold;
- Round 0 saves a baseline; Round 1 and Round 2 each preserve 20 candidates, group balance, and lineage for replacements;
- exactly one winner exists only when a hard-constraint-eligible candidate also meets the configured minimum final score;
- unrun experiments have no result;
- implementation occurs only in implementation scope;
- the default iteration record never exceeds three rounds.

For exact executable fields, read [data-contracts.md](data-contracts.md) and prefer templates generated by the bundled helper over manually reconstructed JSON.
